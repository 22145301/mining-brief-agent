# 日报文件名 = `brief-<数据时点>[-<运行时刻>]-<范围>`：名字回答"这是什么"，不是"我哪天跑的"

文件名由**两段身份**组成：数据时点（回放的锚点 / 实时的那一天）与**范围**（覆盖哪几座矿、新闻窗口多长）。实时模式在日期后**额外**带一段运行时刻（UTC）。原来的写法只有日期（`brief-<数据时点>.md`），本 ADR 改写它。

## 背景：同一天问两个问题，后问的会把先问的盖掉

原写法下文件名与请求无关，只由数据时点的日期决定。后果在 2026-10-09 的 `--live` 验收里真实发生过：先问"Pilbara 锂矿"、后问"今日简报"（整个档案），两次都写 `brief-2026-10-09.md`，**第二份静默盖掉了第一份** —— 事后只从"文件里怎么只有 9 条引用、不是 23 条"才看出来。没有报错、没有日志痕迹，产物就这么少了一份。

这个行为**是被记录过的**（`RUN.md` 的「边界」一节写了"会盖掉上一次的产物，想留就换 `--out`"），所以它不是疏漏，是一条**被低估了的**取舍：原文只把它写成"拒答也会写文件"的附带说明，而实际上**每一份**日报都在互相覆盖。`--out` 能绕开它，但那要求使用者先知道这件事、并且每次都记得改名 —— 把设计缺陷当成使用者要背的注意事项。

回放模式下更彻底：`now` 是冻结锚点，**问什么都写同一个 `brief-2026-10-08.md`**。

## Considered Options

- **文件名加运行时刻（`%H%M%S`）**：`--live` 下确实能解决覆盖，而且用户第一反应正是这个。否决作为**主**方案：它回答的是"我在哪一秒按的回车"，不是"这份日报是什么"。加完之后同一个问题问两遍会得到两个**内容相同**的文件 —— 碰撞换成了重复，读者反而看不出哪些文件说的是同一件事。而且在回放里要它生效就得去抓系统时钟，那正是 ADR-0002 明令禁止的（同一份 fixture 每次跑出不同文件名，产物不再确定）。
- **目标文件已存在就拒绝写入**：改动最小，且绝不丢数据。否决 —— "想重跑一遍同一句话"是极常见的动作，每次都被拦下来要求先手动删文件，是把麻烦从一种形态换成另一种。何况**范围相同**时覆盖本来就是对的（两份产物内容一样，没有东西可丢）。
- **不改，只把 `--out` 写得更显眼**：零代码。否决 —— 见上，"让使用者自己记住"不是修复。
- **文件名只带范围、不带日期**：否决 —— 日期段是 ADR-0002 的既有收益（同一输入 → 同一产物名，可复现），不能为了这个改动把它丢掉。

## Consequences

- **碰撞现在恰好等价于"内容相同"**：范围不同 → 名字必不同；名字相同 → 范围相同 → 两份产物本就该是同一份，覆盖是对的。这是这次改动真正的性质，也是它比"加时间戳"更值的地方 —— 时间戳只是让碰撞更稀有，没有让它有意义。
- **范围一律写全**：点名的矿（超过三座退成 `4-mines`）与窗口（`7d` / `3d`）都落进名字。窗口**不因为等于默认值而省略** —— 省了它，读者只能靠猜"没有这段 = 默认 7 天"，而这个仓库的惯例是把事实写出来让人看。名称示例：`brief-2026-10-08-pilgangoora-7d.md`、`brief-2026-10-08-all-7d.md`。
- **拒答走另一条命名**：`refused-<请求文本的短哈希>`。拒答没有 `scope` 可用，而它同样不该互相覆盖（两次**不同**的越界请求若同名，就又把这次要修的 bug 请回来了）；请求文本是那时唯一稳定的身份，因为它本身就是输入。
- **实时才带运行时刻**。判据是模式，不是"看时间戳准不准"：实时产物**不可复现**（数据源每次给的不一样，这正是不让它入库的理由，见 `.gitignore`），一天跑两遍就是两张不同的世界快照，该各留各的；回放的 `now` 是冻结锚点，把 `17:01:57` 写进文件名只会造出一个**看起来像运行时刻、其实不是**的常量，而这个项目最不肯要的就是"看起来像真的"。时刻口径是 UTC，与数据时点同源，不是本地时间。
- 名字从"日期"扩到"日期 + 范围"，**确定性没有受损**：范围同样是**输入**的函数（`ReportScope` 由请求与档案裁决而来），不是时钟的函数。ADR-0002 要的性质（同一输入 → 同一产物名）原样成立。
