# 录播层存原始响应，回放时以 fixture 锚点时间替代系统时钟

数据层的录播存**抓取时刻的原始响应体逐字节**（LME 的服务端渲染 HTML、mining.com 的 RSS XML、GFEX / DCE 的 JSON），另加一份 `sources.json` 记 URL / SHA256 / 抓取时间 / Content-Type / 状态码；回放时走**完整解析管线**。唯一例外是 PDF —— 存已抽好的 JSON，因为二进制不入库（PRD §10）。

回放模式下**唯一的时间真相来自 fixture**：简报的"今日"、各节数据截止时间戳、`window_days` 的窗口计算，全部从 `sources.json` 的锚点时间推导，不读系统时钟。`--live` 才用真实时钟。

## Considered Options

- **存归一化结果**（`PricePoint[]` / `NewsItem[]`）：fixture 更小更稳，回放不必解析。否决，两个理由。其一，ADR-0001 选"真走 MCP 子进程"的全部收益就是让抓取与解析两层进默认回归，而这两层恰恰是断言最密处（关键词分流 A5、储量表 ground truth A6、逐字引用 A4），存归一化等于把收益砍一半。其二，fixture 会与内部数据类型耦合，类型一改 fixture 全废 —— 那时它不再是"外部世界的替身"，而是"上一版实现的快照"。

## Consequences

- 解析层因此可以是**纯函数**：拿录下来的原始响应直接单测，不需要网络，也不需要起子进程。这是 A5 / A6 那批断言最便宜的落点。
- **回放模式产出的简报日期是过去的某一天，不是运行日** —— 这是刻意的，是 A1 端到端断言可复现的前提（否则今天跑绿、明天跑红）。看到"简报日期 ≠ 今天"时不要当成 bug。
- fixture 的更新方式是重跑一键抓取脚本；`sources.json` 里的 SHA256 让"这份 fixture 对应哪一次真实抓取"可追溯，逐字断言（A4）也就有了明确的 ground truth 出处。
