## Problem Statement

做矿业 / 投资方向的同事，每天早上要自己把当天的信息手工拼一遍：翻 mining.com 和几家公司官网找新闻、挨个开 LME 和国内交易所看报价、再去翻各家公司的技术报告 PDF 捞资源量数字。一轮下来一小时起步。

更要命的是拼出来的东西**没法回溯**——抄进文档的每个数字，半天后就没人说得清它来自哪一版报告、哪个时点的报价。而这几类数据的时效本来就天差地别（技术报告可能是几年前的、LME 只有延迟一日收盘价、国内交易所有当日价），手工汇总时这些差异被一概抹平成"今天的数据"，看上去整齐，实际是把最重要的信息丢了。

而且只要有一个源挂了或者某个矿山不在手上那份清单里，手工流程要么静默漏掉、要么干脆编一个填上。

## Solution

对系统说一句话（如"给我生成一份关于 Pilbara 锂矿的今日简报"），拿到一份 Markdown 矿权日报。

- **六节**：矿权动态、新闻摘要、储量数据、价格走势、风险提示、数据完整性。
- **每个事实带 `[n]`**，指回来源清单里的真实条目；引用块里的 URL / 标题 / 时间戳与工具返回值逐字符相同，由代码校验，不通过就报错。
- **每节标自己的数据截止时间**，抬头写明"各节数据截止时间不同"——这是数据的真实形态，不掩饰。
- **缺什么就说什么**："数据完整性"节列出本次覆盖了什么、缺了什么、为什么缺。任何一节的源挂掉，日报照样出，只是那节标注缺失。
- **不编**：矿名或品种不在档案里，明确说"未覆盖"并列出可选项；超出系统能力（如"预测明年锂价"）则拒答，并回显听懂的部分 + 给可用句式。
- **同一批 MCP server 零改动挂进 Claude Desktop / Cursor**，可以直接手玩三个工具。
- **默认离线可复现**：`git clone` 后 `docker compose up`，不需要任何 API key、不联网、结果确定。

## User Stories

### 出日报

1. 作为矿业 / 投资方向的非技术同事，我想对系统说一句自然语言就拿到日报，这样我不用记任何命令或参数格式。
2. 作为使用者，我想用中文别称、英文名或交易所代码称呼矿山，都能被认出来指的是同一座矿，这样我不用记档案里的规范名。
3. 作为使用者，我想不指定品种和矿山时默认覆盖全部档案，这样我不想挑的时候有完整的一份。
4. 作为使用者，我想不指定天数时默认回溯 7 天，这样"最近"有个可预期的含义。
5. 作为使用者，我想一句话里同时说清楚品种 + 矿山 + 天数，这样一次就能精确框定范围。
6. 作为使用者，我想日报落到文件里并把路径打给我，这样我能把它转发给别人或归档，而不是只能从终端里复制。
7. 作为使用者，我想读到的是一份能直接看的 Markdown，这样我不用再做一次排版。

### 溯源与可信

8. 作为使用者，我想每个事实旁边都有 `[n]`，这样我能知道这个说法是从哪来的。
9. 作为使用者，我想点 `[n]` 就能到原始来源，这样我能自己核实而不是只能信系统。
10. 作为使用者，我想引用块里的 URL、标题、时间戳和原文一字不差，这样我点过去不会落到另一个页面上。
11. 作为使用者，我想"风险提示"节里每条都能读到它依据的权威原文，这样我知道这是监管要求而不是谁的意见。
12. 作为使用者，我想当一条观察够不上逐字引权威原文时它只作为"提示"出现，这样"风险信号"这个词不会被稀释成随便什么观察。
13. 作为使用者，我想看到每节数据**各自的**截止时间，这样我知道我读的价格是今天的还是昨天的、储量是 2023 年的还是今年的。
14. 作为使用者，我想当价格回退到了更早的日期时能看出来，这样我不会把一周前的铜价当成今天的。
15. 作为使用者，我想储量数字标明是资源量还是储量、是哪一级（Measured / Indicated / Inferred 或 Proven / Probable），这样我不会把推断资源量当成可采储量去用。
16. 作为使用者，我想储量数字标明报告体系（NI 43-101 还是 JORC），这样我知道它是按哪套规矩披露的。
17. 作为使用者，我想储量数字能追到 PDF 的第几页，这样我能直接翻过去核对。

### 缺失与拒答

18. 作为使用者，我想在有人为造成的源故障时仍然拿到日报，这样我等了一早上的东西不会因为一个网站挂了就变成一片空白。
19. 作为使用者，我想缺失的那一节明确标注"数据缺失"，这样我不会把空白误读成"没有风险"。
20. 作为使用者，我想"数据完整性"节列出缺了什么以及为什么缺，这样我能判断这份日报今天能不能用。
21. 作为使用者，我想提到一座不在档案里的矿山时被明确告知"未覆盖"并看到可选项，这样我知道是系统不覆盖而不是这座矿不存在。
22. 作为使用者，我想问超出系统能力的问题时（如"预测明年锂价"）拿到一句说清楚边界的拒答，而不是一段编出来的分析。
23. 作为使用者，我想拒答文案里带上可用的句式示例，这样我下一次能问对。
24. 作为使用者，我想拒答时系统回显它听懂的那部分，这样我能看出是哪里没被理解。
25. 作为使用者，我想参数解析不出来时降级为缺省值并在"数据完整性"节记一笔，这样我至少还有一份日报，且知道它是按缺省值出的。

### 三个 MCP server 的复用

26. 作为我自己（评审 / 使用者），我想把三个 server 挂进 Claude Desktop 或 Cursor 后直接手玩 `search` / `fetch_article` / `extract_resources` / `get_price` / `get_trend`，这样我能当场验证它们是真的独立可用。
27. 作为使用者，我想新闻工具返回的每条都带分类（矿权动态 vs 普通新闻），这样"矿权动态"节有确定内容而不是靠系统猜。
28. 作为使用者，我想价格工具按品种自动路由到对应交易所（锂 → GFEX、铜 → LME、铁矿石 → DCE），这样我不用关心去哪家查。
29. 作为使用者，我想查询一个没有数据的日期时拿到明确的"未找到"而不是一个零或一个近似数，这样我不会拿编出来的价格做判断。
30. 作为使用者，我想价格返回值里同时有"我要的日期"和"实际给到哪天的数据"，这样回退是可见的而不是静默的。

### 离线、可复现、可维护

31. 作为维护者，我想 `pytest` 默认不联网就全绿，这样 CI 里不会因为外部网站抽风而红。
32. 作为维护者，我想默认运行模式不需要任何 API key，这样陌生人 clone 下来就能跑，不用先跟我申请凭证。
33. 作为维护者，我想 `--live` 是唯一的实时开关，这样"这次会不会真的联网"没有第二种解释方式。
34. 作为维护者，我想离线确定性由录制层保证（数据抓取与 LLM 响应都录），这样同一个请求跑两次结果一致。
35. 作为维护者，我想回放数据里查出缺一份录播时直接报错，而不是悄悄去打真实网络，这样"离线确定性"不会被一次静默的网络调用破坏。
36. 作为维护者，我想调一句导读的措辞时不必被迫把铜价源切到真实抓取，这样高频的小改动不会拖上整条需要浏览器的链路。
37. 作为维护者，我想 `docker compose up` 就产出日报而不需要任何配置，这样我能把"5 分钟跑起来"这句话兑现。
38. 作为维护者，我想 lint、格式化、类型检查一把跑过，这样我不用靠人眼维持风格。
39. 作为维护者，我想 MCP server 只做参数校验和转发、业务逻辑留在别处，这样工具级测试不会退化成同一份逻辑的第二次复制。
40. 作为维护者，我想关键取舍在 `docs/adr/` 有记录，这样有人想"顺手改好"某个刻意的设计时能找到理由。

### 如实声明取舍

41. 作为评审人，我想看到 README 里写明哪些行业标准价（Platts IODEX / Mysteel / SMM / Fastmarkets）因为付费墙拿不到，这样我能判断系统的数据边界是设计选择还是能力缺口。
42. 作为评审人，我想看到它写明了用 LME 延迟收盘价而非实时价、以及为什么没有换 SHFE，这样我能看出作者知道自己在取舍什么。
43. 作为使用者，我想知道铁矿石这一档标的是"知难而选的妥协项"，这样我不会以为它和铜、锂是同等质量的数据。
44. 作为评审人，我想看到系统区分了资源量与储量（而不是沿用题面的笔误），这样我能判断作者是真懂这行还是照着题面抄。

## Implementation Decisions

### 交付面

- 交付 `README.md`（门面：项目是什么、架构一页、装 / 跑 / 测三条命令、badge、指向 `docs/adr/`）与 `RUN.md`（题面点名的 5 分钟通道：clone → `docker compose up` → 产物在哪）。题面点名的文件是 `RUN.md`，CLAUDE.md 要求的是 README，两者各司其职、不复制内容。详见 PRD §11.1。
- `mcp-config.json` 与题面同名放仓库根目录，用于把三个 server 挂进 Claude Desktop / Cursor。
- `docker compose up` 只起**一个** `brief` 服务：跑完整链路、把日报写到挂载出来的 `out/`。三个 MCP server 不进 compose。

### 包与分层

代码放在**一个**可安装包 `mining_brief/` 里，按层分子包：`contracts`（返回信封与共享数据结构）/ `datasources`（抓取与解析）/ `servers`（三个 MCP server 的薄壳）/ `agent`（LangGraph 编排）/ `config`（只放非密钥配置：矿权档案、交易所表、窗口缺省与超时重试参数）。

`fixtures/` 与 `scripts/` 留在包外——它们是数据与工具，不是产品代码。**ADR-0008。**

三条纪律：

1. **MCP server 是薄壳**：只做"参数校验 → 调 adapter → 包成信封"，业务逻辑一行都不留在 server 里。往 server 里搬逻辑会让工具级测试退化成同一份逻辑的第二次复制。
2. **`config/` 只放非密钥配置**；密钥与 LLM key 走环境变量 + `.env.example`。
3. 不用多包工作区（对 24h 面试任务不成比例）。

### 数据源层：两段式

数据源层拆成 `Fetcher`（`fetch(url) -> RawResponse{body, content_type, status, fetched_at}`，实现有 HTTP / 无头浏览器 / fixture 回放三种）与 `Parser`（纯函数 `parse(raw) -> T`）两段，**adapter 只做编排**。

任何 adapter 里都**不出现** `if replay` 分支——模式差异全部收在 Fetcher 的实现选择上。**ADR-0003。**

硬事实：三个价格源里**只有 LME 需要无头浏览器**（Cloudflare 拦所有 HTTP 客户端，值在 `span.hero-metal-data__number`）；GFEX 与 DCE 可直接 HTTP 抓取。

### MCP 工具的返回契约

每个工具返回一个顶层信封（`NewsSearchResult` / `ArticleLookup` / `PriceLookup` / `PriceSeries` / `ResourceExtract`）。"已获取 / 确实无数据 / 降级"是**正常字段**（`status` / `source_status` / `reason`），只有无效参数才抛异常。

后果：数据源故障被吸收进信封，于是图只需要隔离"工具链本身失效"这一种情况。**ADR-0005。**

工具签名照题面，不自创。`get_price` 返回**不晚于 `requested_date` 的最近可得值**，同时携带 `as_of` 与 `requested_date`；`delayed` 保持"数据源固有延迟"的含义（LME 恒为 `true`），**不**用来标记回退——回退一律由 `as_of < requested_date` 表达，不设独立标志位。**ADR-0004。**

### 回放层

- 默认（回放）模式**照常走 MCP 协议**，但用 SDK 的**进程内协议连接**，不起 stdio 子进程；由环境变量 `MINING_DATA_MODE` 决定读 fixture 还是抓网络，调用方一行都不用改。
- stdio 传输由两处覆盖：一个冒烟用例 + `mcp-config.json` 挂进宿主。**ADR-0001。**
- fixture 存**逐字节原始响应体**，加上 `sources.json`（URL / SHA256 / 抓取时间 / Content-Type / 状态）。唯一的例外是 PDF——存预抽好的 JSON（二进制约 130 MB 且受版权保护）。
- 回放时的时间 = **fixture 锚点时间**，不是系统时钟。因此回放产出的日报带的是过去的日期，这是有意的。**ADR-0002。**
- LLM 层复用同样的形状：一个 `LLMClient` 协议，`live` 与 `replay` 两个实现。回放的 key 是 `(节点名, 关键输入字段的规范化哈希)`——哈希的是**输入数据**而非 prompt。**回放时查不到 key 直接报错，绝不 fallback 到真实调用。**
- 数据层与 LLM 层用**两个独立开关**：`MINING_DATA_MODE` 与 `MINING_LLM_MODE`，各自 `replay | live`，都默认 `replay`；`--live` 是把两个都置为 `live` 的语法糖。分开的理由：调一句导读的措辞不该被迫把铜价源切到真实抓取（那要无头浏览器、要过 Cloudflare）。**ADR-0009。**

### Agent 编排

九个节点，**模型只出现在第 1、2、7 个**，其余全是纯函数。并行扇出是**静态三边**（三个 fetch 节点互不依赖），不用 `Send` API。

| # | 节点 | 谁在决策 | 失败时 |
|---|---|---|---|
| 1 | `parse_intent` | LLM | 降级为缺省值 |
| 2 | `resolve_entities` | LLM + 档案 | 同上，对不上记"未覆盖" |
| 3 | `check_scope` | 纯函数 | 不在覆盖内 → 拒答 → END |
| 4a-4c | `fetch_news` / `fetch_prices` / `fetch_resources` | MCP 工具 | 记入"数据完整性"，简报继续 |
| 5 | `compute_signals` | 纯函数 | 记错，该节留空 |
| 6 | `assemble` | 纯函数 | —（逐字引用块由代码塞入，不由模型生成） |
| 7 | `narrate` | LLM | 降级为不写导读 |
| 8 | `verify_citations` | 纯函数 | 不通过 → 报错 |
| 9 | `render` | 纯函数 | — |

**state schema**（扁平 `TypedDict`，**没有任何 reducer**；每个 fetch 节点写自己的 key，缺失由 `assemble` 从三个信封推导，而非往共享列表里累积）：

```python
class BriefState(TypedDict):
    request_text: str
    now: datetime                      # 回放模式下 = fixture 锚点时间
    slots: Slots
    scope: Scope | None
    uncovered: list[str]
    refusal: Refusal | None
    news: NewsSearchResult | None
    prices: dict[str, PriceSeries] | None
    resources: ResourceExtract | None
    signals: list[RiskSignal]
    sections: list[Section]
    narratives: dict[str, str]
    citation_report: CitationReport | None
    output_path: str | None
```

**ADR-0007。**

**每个 fetch 节点各自 `try/except` 兜底**，返回降级信封；`RetryPolicy(max_attempts=3, backoff_factor=2.0)`。纯函数节点**不**重试也不捕获；LLM 节点重试 API 层错误（`max_attempts=2`）并按上表降级。

> ⚠️ **不要把这层 try/except 当冗余删掉。** LangGraph 的 superstep 是事务性的：一个并行分支抛异常会让整个 superstep 回滚、整张图抛错，且没有 checkpointer 时兄弟分支的成功结果也会一起丢失。PRD §6.2 的"任一 fetch 挂掉，简报照样出"**不是框架默认行为**。**ADR-0006。**

三个 fetch 节点写成 `async def`，超时只放在配置里（HTTP 15s、无头浏览器 45s，是起点，实现后按实测校准）。

### 风险提示的规则来源

规则必须来自权威公开内容，**不得自行编造**。规则集收窄至能逐字引到原文的条目（JORC 2012 / NI 43-101 的法定披露要求、ASX Listing Rule 5.16 的法定警告句），引不到原文的降级为"提示"，不进入"风险信号"。

### 数据源与档案

档案 8 个矿山 / 3 个矿种，每条含 `id / 公司 / 项目 / 矿种 / 交易所代码 / 中文别称 / 技术报告 URL / 报告日期`。**实体解析只以档案为准**，匹配不上就是"未覆盖"。

价格路由：锂 → GFEX 碳酸锂；铜 → LME；铁矿石 → DCE。

README 需如实写明拿不到的东西：Platts IODEX / Mysteel / SMM / Fastmarkets 全部付费墙；LME 实时价需机构注册，只能用官网延迟收盘价；铜的备选 SHFE 未采用（server 名是题面定的）。铁矿石标的是"知难而选的妥协项"（主流铁矿公司走 20-F、不出 NI 43-101，Fortescue 是例外）。

### 术语纪律

产出物节标题沿用题面措辞（**「储量数据」**），但节内数据严格按真实类别标注：Indicated / Inferred 是**资源量**不是储量，与 Proven / Probable 是不同类别。题面把两者混称是笔误（同一份题面的题 #3 用对了词）。README 的数据源声明里记一笔。其余术语一律以 `CONTEXT.md` 为准。

## Testing Decisions

### 什么算好测试

**只测外部行为，不测实现细节。** 断言落在产物和返回值上——简报 Markdown 的内容、工具返回的信封字段——而不是中间变量、内部调用次数或私有函数。判断标准是：重写内部实现但保持行为不变时，测试应该一条都不用改。

第二条纪律来自 PRD §12：**ground truth 不得引用二手数字**，否则测试是自证。同一条纪律的推论是——**绿色路径证明不了检查器在工作**：`verify_citations` 全过，可能只是因为它什么都放过。所以否定测试不可省。

### 三条切面

仓库目前没有代码，三条切面都是新设的。数量压到 3，每条都被断言逼着存在。

**S1 — 图入口（最高切面）**
`graph.ainvoke(BriefState)` 跑在默认回放模式。一次调用穿过 CLI → 9 个节点 → 进程内 MCP 协议连接 → 三个 server → Fetcher / Parser / adapter → 渲染出文件。断言看**产物**（简报文件 + 返回的 state），不看中间变量。覆盖 A1 / A3 / A4 / A7 / A8 / A9。

**S2 — 进程内 MCP 工具连接**
`async with Client(mcp)` 直连每个 server 的每个工具，与 S1 同一份 fixture，入口换到工具级。覆盖 A2，以及 A5 / A6（category 分流与资源量抽取由拥有它们的工具负责）。`@pytest.mark.network` 的真下载真解析用例**复用同一条切面**，只把 `MINING_DATA_MODE` 换成 `live`，不新开缝。

**S3 — 纯函数节点直调，且只写否定测试**
只放"必须失败"的用例：坏 `[n]` 必须让 `verify_citations` 报错、越界请求必须拒答。**不给纯函数写"正常输入 → 正常输出"的测试**——那些 S1 已覆盖，再写一遍是复制品测试（同 ADR-0008 里 server 薄壳那条纪律）。

A7 的故障注入走**数据**而非代码：用一份故障 fixture 集（原始响应里带 503 body），不打桩。

ADR-0001 要求的 stdio 冒烟是唯一例外，一个用例、单独标记，不构成常规切面。

### 断言与切面的对应

| 断言 | 切面 | 怎么测 |
|---|---|---|
| A1 端到端出简报 | S1 | 题面原句 → 跑 → 断言六节齐、文件落盘 |
| A2 每工具单测、离线全绿 | S2 | 逐工具，默认 `replay` |
| A3 引用通过率 100% | S1 + S3 | S1 断言产物能出（出不了就是 verify 拦下了）；S3 补否定用例 |
| A4 引用块逐字相同 | S1 | 拿 fixture 里的原始字符串直接比，不比"语义等价" |
| A5 category 分流 | S2 | 断言 `search` 返回值里每条 `category` |
| A6 PDF 对 ground truth | S2 | 回放比冻结值；`network` 标记的版本真下载真解析 |
| A7 单源故障仍出简报 | S1 | 故障 fixture 集，不往代码里打桩 |

### 被测模块

`contracts`（信封结构的字段完整性）、`datasources` 的解析层与三个价格 adapter 的路由与回退、`servers` 的三个工具（S2）、`agent` 的整图（S1）与两个纯函数检查器（S3，仅否定）。

### 既有先例

仓库还没有代码，没有可参照的既有测试。首次落地时由其中一条工具级测试（S2）确立风格，其余跟上。风格要求：命名讲清行为而非实现（`test_get_price_falls_back_to_earlier_date` 而不是 `test_get_price_2`）、每个测试只断言一件事、fixture 通过 `pytest` fixture 而不是 import 时读取。

## Out of Scope

PRD §2.2 的非目标，本轮明确不做：

- **N1 预测、估值、投资建议** —— 无数据支撑，且题面要的是"日报"。越界请求一律拒答。
- **N2 自由问答** —— 单一意图。开放问答会退化成聊天机器人。
- **N3 矿权登记簿级别的权威数据** —— 没有公开免费源，硬接就是编。档案是自带的 8 条，不是权威登记簿。
- **N4 全市场覆盖** —— 档案 8 个矿山；超出即明确拒答，不幻觉。

另外明确不做：实时推送或常驻服务（`docker compose up` 跑完即退，是一次性 job）；SSE / HTTP 传输（只用 stdio）；多用户与权限（单人内部工具）；调度与定时出报；Lithium Americas — Thacker Pass（其技术报告在 EDGAR 上是 HTML exhibit 而非独立 PDF，混入会让解析层多一条分支）。

### 从 PRD §13 继承的已知缺口

| | 缺口 | 影响 | 处置 |
|---|---|---|---|
| R1 | 风险规则的原文级引用未完成 | "风险提示"节无法冻结 | 实现前专门做一轮，规则集宁窄勿编——引不到原文的降级为"提示" |

R2 与 R4 合起来的后果值得说清楚：**默认路径覆盖的是"读冻结 JSON → ResourceTable"这一段**，"真下载真解析"只在带标记的用例里跑到。这是接受了的取舍，不是遗漏。

### 数据源的已核实事实

以下都在配置阶段实测过，不要再当成假设：三个价格源里只有 LME 需要无头浏览器（Cloudflare 拦全部 HTTP 客户端）；GFEX 与 DCE 可直接 HTTP 抓取；mining.com RSS 需要浏览器 UA；SEC EDGAR 需要带邮箱的 UA。

### 题面里的事实错误（面试可讲）

这些不是抄错，是核对过的：

- Pilbara Minerals 已更名为 **PLS**。
- 中国稀土集团官网是 `regcc.cn`。
- 锂（碳酸锂）在 **GFEX**，不在 SHFE。
- 题面把 Indicated / Inferred 称作"储量"，实际是**资源量**；同一份题面的题 #3 用对了词。

### 需要准备的追问

- **"为什么用 MCP 而不是直接函数调用？"** 三条答案：工具契约独立可测；同一批 server 零改动挂进 Claude Desktop / Cursor（能当场演示，且是题面交付项）；传输层与业务解耦（stdio 换 SSE 不动业务代码）。而"LLM 不做工具选择"是**设计主张**——日报的数据采集是固定流程，把工具选择交给模型只会引入不确定性。
- **"为什么用图而不是顺序脚本？"** 答案只有一条：4a / 4b / 4c 并行且各自需要独立的超时、重试、失败降级。
- **"为什么 server 这么薄？"** 见 ADR-0008 的纪律：逻辑搬进 server，工具级测试就退化成同一份逻辑的第二次复制。
- **"那层 try/except 不是冗余吗？"** 见 ADR-0006：LangGraph superstep 事务性，删掉就破坏了"一个源挂了日报照样出"。
